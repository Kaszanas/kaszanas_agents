# MAT001: if/elif chain that reads better as a `match` statement

Derived from the **python-match-statements** standard. Fix: **available** when reported
with `[*]`. Requires a project targeting Python 3.10 or later.

## What it does

Flags if/elif chains of at least `min-match-branches` branches (default 3, counting
`else`) where every test checks the **same subject** against a pattern. Where it's
provably equivalent, the fix rewrites the chain as a `match` statement.

## Why is this bad?

A long if/elif chain repeats the subject in every test, and hides the fact that the code
is dispatching on one value. `match` states the subject once and lists the alternatives
as data: `case "GET" | "HEAD":`, `case None:`, `case int() | float():`. Coding agents
rarely use `match` unless prompted.

**This is a readability rule, not a performance rule.** CPython compiles `match` into
the same sequence of compare-and-jump instructions as if/elif, with no jump table.
Measured, literal patterns are about as fast as `==` chains, and class patterns are
slower than `isinstance` chains. See
[the benchmarks](../../../docs/benchmarks/match-statements.md). If you need speed for
value→constant maps, use a dict ([MAT002](MAT002.md)).

## Example

```python
if command == "start":
    run()
elif command in ("stop", "halt"):
    shutdown()
elif command is None:
    usage()
else:
    error(command)
```

Use instead:

```python
match command:
    case "start":
        run()
    case "stop" | "halt":
        shutdown()
    case None:
        usage()
    case _:
        error(command)
```

| Test                                           | Pattern                        |
| ---------------------------------------------- | ------------------------------ |
| `x == 1`, `x == "a"`, `x == -2.5`, `x == b"a"` | `case 1` (literal)             |
| `x == Color.RED` (dotted name)                 | `case Color.RED` (value)       |
| `x is None` / `x is True` / `x is False`       | `case None` / `True` / `False` |
| `x in (1, 2)` / `x == 1 or x == 2`             | `case 1 \| 2`                  |
| `isinstance(x, C)` / `isinstance(x, (A, B))`   | `case C()` / `case A() \| B()` |
| `x == 1 and ready`                             | `case 1 if ready`              |
| `else:`                                        | `case _:`                      |

## Fix safety

The fix is offered only when the rewrite is provably equivalent:

- the subject is a name or a dotted attribute (evaluated once by `match`, so calls and
  subscripts never qualify). With an attribute subject, guards may not call functions;
- every class in a class pattern is verified to be a class: a project class, a builtin,
  or a stdlib class. `isinstance(x, TYPES)` with a tuple variable would make
  `case TYPES():` raise;
- bodies are copied verbatim and re-indented. Comments move with them, and a comment on
  an `if`/`elif`/`else` line moves to its `case` line;
- the layout can be reproduced exactly. No multi-line strings in the chain (re-indenting
  would change them), no tab indentation, no bodies on the header line, no comments
  inside a multi-line condition.

Otherwise the chain is reported without `[*]`. Every fixed file is re-parsed before it's
written.

## When it is not reported

- `x == RED` with a **bare name**. `case RED:` would be a *capture pattern* that matches
  everything and rebinds `RED`.
- `x == None` / `x == True` / `x == False`, because `==` and `is` differ (`1 == True`).
- `!=`, `<`, `is not`, membership in a set literal (raises for unhashable subjects), or
  tests on different subjects.
- `else:` followed by a nested `if`. Only real `elif` chains count.
- The chain is a [MAT002](MAT002.md) dict-lookup candidate (that rule takes precedence).
- The project targets Python older than 3.10. This uses `target-version`, then
  `requires-python`, then ruff's `target-version`.

## Configuration

```toml
[tool.kaszanas-lint]
min-match-branches = 3      # if + elif + else count as 3
target-version = "py310"    # optional; detected from requires-python otherwise
```

Suppress one chain with `# noqa: MAT001` on its `if` line.
