# CMT001: decorative banner comment around a section title

Derived from the **source-section-comments** standard. Fix: **always available** (safe).

## What it does

Flags full-line comments that decorate a section title with runs of 4 or more repeated
characters (`-`, `=`, `*`, `#`, `~`, `_` or `+`):

```python
# ------------------------------------------------------------------ scopes
# ==== Public API ====
#### Helpers ####
# Private helpers ****
```

It also flags a **block** of adjacent comment lines that is just decoration around one
title line, as a single finding:

```python
# ------------------------------------------------------------
# Some helpers
# ------------------------------------------------------------

# ------------------------------------------------------------
# Rendering methods

# Date/time conversion
# --------------------

# ==========
#
#   saxutils tests
#
# ==========
```

A block is a run of full-line comments on consecutive lines at the same column. It
counts as a decorated title when it contains at least one divider line and exactly one
line with text. Bare `#` lines count as decoration.

## Why is this bad?

The decoration carries no information. It makes the title harder to grep, and it adds
noise to every diff that touches the line. It goes stale when someone re-indents the
code or the line length changes. Editors and documentation tools already understand
plain comments, docstrings and module boundaries. A section that needs a big banner is
usually a sign that the module should be split.

## Example

```python
class Checker:
    # ------------------------------------------------------------------ scopes
    def scope(self): ...
```

Use instead:

```python
class Checker:
    # Scopes:
    def scope(self): ...
```

## Fix safety

The fix is always safe, because it only rewrites full-line comments. It replaces the
banner, or the whole block, with `# Title:` at the same indentation:

- a plain lowercase first word is capitalized (`some helpers` becomes `Some helpers`);
- identifiers keep their spelling (`update_wrapper()`, `camelCase`);
- leftover box borders and end punctuation (`:`, `.`, `!`, `?`) are stripped, so the
  colon is never doubled;
- line endings (LF or CRLF) are preserved.

The fix was verified on Django, the CPython standard library and pandas. It rewrote
banners in 268 files, and every rewritten file has exactly the same AST as the original.

## When it is not reported

- Comments after code on the same line (`x = 1  # ---- note ----`).
- Text in strings and docstrings.
- Mixed-character art such as table borders or diagrams (`# +-----+`,
  `# |  A  |---->| B |`). Decoration runs in the middle of text are not reported either.
- Runs shorter than 4 characters (`# --- note`, Markdown-like `## Heading`,
  `### Sub ###`).
- ASCII bar and interval diagrams such as `# x: ---  -----` (a `label:` followed only by
  bars, or several groups of bars).
- Titles with fewer than two letters or digits.
- Comments that carry tool directives (`noqa`, `type:`, `fmt:`, `pragma`, `pylint:` and
  so on), coding declarations and shebangs.
- A block whose dividers surround several lines of text. Its dividers are reported one
  by one as [CMT002](CMT002.md), and the text stays.
- Non-Python files. Banners are fine in Makefiles, shell and config files, which
  kaszanas-lint never reads.

## Configuration

There are no options. Select or ignore the code as usual:

```toml
[tool.kaszanas-lint]
per-file-ignores = { "generated/**" = ["CMT001", "CMT002"] }
```

Suppress one banner with `# noqa: CMT001` on its first line.
