# KWA002: too many positional arguments in a call to external code

Derived from the **python-keyword-arguments** standard. Fix: **none** (report only).

## What it does

Flags calls to code outside your project (standard library, third-party, or anything
that can't be resolved statically) that pass more than `max-positional-external`
(default 2) positional arguments.

## Why is this bad?

`re.sub(pattern, replacement, text)` relies on the reader remembering the parameter
order of a function they didn't write. Past two arguments, positional calls to external
APIs are a common source of swapped-argument bugs.

## Example

```python
re.sub(r"\s+", " ", text)
```

Use instead:

```python
re.sub(pattern=r"\s+", repl=" ", string=text)
```

For builtins and standard-library functions, the message names the keywords to use, read
from the real signature.

## Fix safety

There's no automatic fix. Third-party signatures aren't known statically, and stdlib
parameter names can differ between Python versions.

## When it is not reported

- The call passes at most `max-positional-external` positional arguments.
- The extra arguments are positional-only or land in `*args`, according to the builtin
  or stdlib signature: `isinstance(x, T)`, `os.path.join(a, b, c)`, `max(a, b, c)`.
- The dotted call name matches `ignore-call-patterns`. By default, logging methods
  (`logger.info("%s %s", a, b)`) and string helpers are ignored.
- The call unpacks `*iterable`.

## Configuration

```toml
[tool.kaszanas-lint]
max-positional-external = 2
extend-ignore-call-patterns = ['(.*\.)?assert\w*']
inspect-stdlib = true
```

Suppress one call with `# noqa: KWA002`.
