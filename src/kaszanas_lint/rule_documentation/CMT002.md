# CMT002: decorative divider comment line

Derived from the **source-section-comments** standard. Fix: **always available** (safe).

## What it does

Flags full-line comments made of nothing but one decoration character, repeated at least
4 times (`-`, `=`, `*`, `#`, `~`, `_` or `+`, with optional spaces):

```python
# ------------------------------------------------------------
# ============================================================
##########
# = = = = =
```

## Why is this bad?

A divider line says nothing. Blank lines, a `# Title:` comment, a docstring or a
separate module structure the code better. Long dividers also break whenever the line
length or the indentation changes.

## Example

```python
import os


# ============================================================


def helper():
    return os.sep
```

Use instead:

```python
import os


def helper():
    return os.sep
```

## Fix safety

The fix is always safe, because it only deletes a full-line comment. When the divider
sits between blank lines, the gap that remains is the larger of the two original gaps,
so two blank lines, a divider and two blank lines become two blank lines.

Dividers next to a single title line (above it, below it or both) are reported as one
[CMT001](CMT001.md) finding instead, and the block becomes `# Title:`. CMT002 covers
dividers that stand alone, or that sit in a comment paragraph with several lines of
text.

## When it is not reported

- Dividers shorter than 4 characters (`# ---`).
- Mixed characters such as table borders (`# +-----+-----+`), and table-header
  underlines with wider gaps (`# ----    -----`).
- Comments after code, and text in strings and docstrings.
- Non-Python files. Dividers are fine in Makefiles, shell and config files, which
  kaszanas-lint never reads.

## Configuration

There are no options. Suppress one divider with `# noqa: CMT002` on the same line, or
ignore the code for some files:

```toml
[tool.kaszanas-lint]
per-file-ignores = { "generated/**" = ["CMT002"] }
```
